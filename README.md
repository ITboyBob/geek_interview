# README.md

本仓库是我准备福利题的过程记录
全过程分为如下几个环节
1. 用户需求分析：输入是福利题上的“用户原始问题描述”。本环节针对原始问题描述进行多角度拆分，关键是通过流程拆解定位用户的阻塞点。最终输出是若干阻塞点/痛点
2. 痛点验证和确认：输入是上一环节得到的若干阻塞点/痛点假设。本环节首先将这些阻塞点转换为“可被验证的假设”，然后针对每种假设调研论坛（本次调研范围是Reddit）真实用户评价，旨在验证用户是否出现相关阻塞行为。最终把原有的阻塞点假设收敛到2个假设，具体见`痛点确认.md`
3. 竞品分析：输入是已经确认的2个假设。本环节通过调研现有竞品，主要回答3个问题：现有竞品是如何解决满足2个产品假设的？除了2个产品假设，现有竞品还有哪些被用户称赞的功能？除了2个产品假设，现有竞品有哪些failure mode被用户吐槽，我们可能要避免？这3个问题的答案将用于指导下一环节
4. PRD撰写：输入是竞品分析得到的3个原则。本环节首先确定第一阶段产出物为MVP形态的产品。其次，在上一环节3个原则的限定下，我做出适当调整，最终交付了1份PRD草稿，囊括了产品MVP阶段的主要功能
